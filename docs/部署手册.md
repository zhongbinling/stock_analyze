# 部署手册

> 适用于 v1.0.0（第一阶段完整版）。English: [DEPLOY.md](en/DEPLOY.md)
> 三平台统一入口：`scripts/` 下的 service（服务管理）与 deploy（一键部署）脚本。

## 1. 环境要求

| 项 | 要求 |
|---|---|
| Python | 3.10+（3.12/3.14 均验证过） |
| 网络 | 能访问 github（克隆/更新）与东财/同花顺行情接口 |
| 磁盘 | < 500MB（含依赖与数据） |

## 2. 一键部署（推荐）

### Windows

```bat
git clone https://github.com/zhongbinling/stock_analyze.git
cd stock_analyze
scripts\deploy_win.bat
```

### macOS / Linux

```bash
git clone https://github.com/zhongbinling/stock_analyze.git
cd stock_analyze
./scripts/deploy_mac.sh      # 或 ./scripts/deploy_linux.sh / ./scripts/deploy.sh
```

部署脚本自动完成：检查 Python → 创建 `.venv` 虚拟环境 → 安装依赖 → 数据库迁移 → **无账号时交互创建超级管理员**（已有则跳过）→ 可选注册开机自启 → 启动服务 → 健康检查并打印访问地址。

## 3. 服务管理（三平台命令一致）

| 命令 | Windows | macOS / Linux |
|---|---|---|
| 启动 | `scripts\service.bat start` | `./scripts/service.sh start` |
| 停止 | `scripts\service.bat stop` | `./scripts/service.sh stop` |
| 状态 | `scripts\service.bat status` | `./scripts/service.sh status` |
| 重启 | `scripts\service.bat restart` | `./scripts/service.sh restart` |
| 注册自启 | `…install` | `…install` |
| 卸载自启 | `…uninstall` | `…uninstall` |

- `start` 会先做幂等数据库迁移，再后台启动；已运行则拒绝重复启动（探活 `/healthz`）
- 运行日志：`data/service.log`；PID：`data/service.pid`
- 自启实现：Windows=注册表 HKCU Run 键（登录时，用户级免提权），Linux=systemd 单元（需 sudo），macOS=launchd（用户级）
- 脚本优先使用 `.venv` 解释器，不存在则用系统 Python（兼容全局部署）

## 4. 部署后初始化

```bash
# 1) 管理端登录(部署时已建超管): http://127.0.0.1:8501/admin/login
# 2) 首次拉取行情数据(~8-12分钟): 管理端 → 数据管理 → 增量更新数据

# 4) 用户访问: http://127.0.0.1:8501/mkt (免登录)
```

## 5. 手动部署（不用脚本）

```bash
cd stock_analyze
python -m venv .venv && .venv/bin/pip install -r requirements.txt   # Win: .venv\Scripts\...
export FLASK_APP="server:create_app()"     # Win: set
python -m flask db upgrade                # 迁移
python -m server.bootstrap --username admin   # 首次建超管(交互)
python -m server                          # 前台运行(waitress, Ctrl+C停)
```

## 6. 升级

```bash
cd stock_analyze && git pull
scripts\service.bat restart        # 或 ./scripts/service.sh restart (start自带幂等迁移)
# 依赖有变时: .venv\Scripts\pip install -r requirements.txt 后再 restart
```

## 7. 备份与恢复

### 7.1 自动备份（推荐，服务化 · B1）

数据库不入 git 且含密码哈希/密钥，务必开启自动备份。SQLite 用在线备份 API 快照，
不拷贝正在写入的库；每份快照落盘即完整性校验，sha256 记入 `backups/manifest.json`；
内容未变化自动跳过。

**首选：服务内备份（数据管理页 → 数据备份）**
- [立即备份]：手动/日备/周备三选一点击即执行（走任务队列，与数据任务互斥）
- 自动任务：日备（默认每日 18:35）+ 周备（默认周五 18:45），策略页可改、热生效
- 保留策略可配：日备默认 14 份、周备 8 份、手动 5 份（每资产每类型滚动，最新一份永不删）
- 历史表：时间/类型/文件数/大小/耗时/状态，逐行可 [校验]（全量 sha+integrity）与 [恢复]
- 日志双轨：`backups/backup.log` 文件 + app.db `backup_runs` 表
- 高危前置快照：`sector.py calc` 全量重算前自动打 `pre-calc`；恢复前自动打 `pre-restore`
- app.db 恢复需停服后命令行执行（服务自身数据库不能在线替换）

**应急/命令行（CLI 保留）**：
```bat
cd core
python backup.py daily             # 日备+清理   weekly 同理
python backup.py list              # 清单(含类型)
python backup.py verify --all      # 全量校验
python backup.py restore <文件名> --yes   # 恢复(含app.db, 需停服)
```

**旧计划任务**：`scripts/install_backup_task.bat` 注册的每日 18:30 任务已被服务调度取代，
用 `scripts/uninstall_backup_task.bat` 卸载（避免日志双份）。

## 8. 常见问题

- **端口被占**：`config/server.yaml` 改 `port` 后 restart；或 `netstat -ano | findstr 8501`（Linux: `lsof -i:8501`）找残留进程
- **局域网访问**：`host` 改 `0.0.0.0` + 防火墙放行端口；**建议加 HTTPS 反向代理**（服务自身无 TLS、无互联网加固）
- **忘记超管密码**：`python -m server.bootstrap --username admin2 --force` 新建超管，登录后在账号管理删除旧号
- **迁移失败**：`python -m flask --app "server:create_app()" db upgrade` 单独执行看报错；`db current` 查看版本
- **数据更新失败**：多为行情源限流，稍后重试；数据管理页可看任务日志；指数K线东财→腾讯→tushare三重回退
- **tushare（可选增强）**：数据管理页→数据源→tushare 填入 token 保存即生效（本地存储不入 git）；
  提供交易日历与指数日线第三回退；涨跌停名单等高积分接口未接入
- **服务起不来**：查 `data/service.log` 尾部；常见为依赖未装全（重跑 deploy）或 8501 被占
- **Windows 找不到 python**：安装时勾选 *Add python.org to PATH*，或用 `py -3` 手动装依赖后直接 `python -m server`
