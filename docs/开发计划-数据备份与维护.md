# 开发计划 · 核心资产备份与维护

> 状态：**已确认（2026-10-18）** · 定位：独立运维工作流（与第四阶段服务运维互补）
> 背景：数据库不入 git（含密码哈希/密钥），丢失不可再生（用户账号、视图规则、手工别名、
> 东财已下架历史段）；本地按天备份只能防误删与代码写坏，防不了硬件损坏与慢性损坏

## 设计原则

1. **可验证的备份才算备份**：每份快照落盘即 `PRAGMA integrity_check` + 数据新鲜度抽查，sha256 记入 manifest
2. **一致性快照**：SQLite 用在线备份 API（`Connection.backup()`），不拷贝正在写入的库（calc 每晚 VACUUM）
3. **GFS 分层保留**：30 日 + 12 周（每周最后一次快照）+ 12 月 —— 慢性损坏 40 天后仍可回溯一年
4. **高危操作前置快照**：`sector.py calc` 全量重算前自动打 `pre-calc` 标签快照（防自己的代码写坏数据）
5. **恢复必须演练**：`verify` 子命令随时校验任意快照；恢复前自动打 `pre-restore` 快照兜底

## 实现（`core/backup.py`）

| 子命令 | 行为 |
|---|---|
| `now [-t tag]` | 立即快照全部资产；sha256 与该资产最近一次相同 → 跳过（节假日不占空间） |
| `daily` | `now` + `prune`（任务计划程序每日入口，收盘任务链后 18:30） |
| `prune` | GFS 清理：每资产保留 最近30份 ∪ 最近12个ISO周各1份(周内最新) ∪ 最近12个月各1份 |
| `list` | 备份清单（时间/资产/大小/标签/校验状态） |
| `verify [file\|--all]` | 文件存在 + sha256 比对 + integrity_check + 新鲜度查询 |
| `restore <file> --yes` | 先校验 → 打 pre-restore 快照 → 原子替换目标 |

- 备份目录 `backups/`（gitignore）；清单 `backups/manifest.json`
- 命名 `{asset}_{YYYYMMDD_HHMMSS}[_{tag}].db|.bin`
- 资产缺失 → 告警跳过不报错（各环境资产集不同）

## 调度与文档

- `scripts/backup_daily.bat`（CRLF）：`python core\backup.py daily >> backups\backup.log`
- `scripts/install_backup_task.bat`：`schtasks /Create ... /SC DAILY /ST 18:30`（独立于 Web 服务存活）
- `docs/部署手册.md` 增补「数据备份与恢复」：安装、手工恢复步骤、异地副本建议
  （robocopy 镜像第二块盘 + 7z AES-256 加密同步网盘——库内含密码哈希与 token，明文不上云）

## B1-1 服务端备份能力（`server/backup.py` + `core/backup.py` 改造）

**保留策略可配置**（`config/server.yaml`，管理页可改）：
```yaml
backup:
  enabled: true
  daily_n: 14        # 日备份滚动保留份数
  weekly_n: 8        # 周备份滚动保留份数
  monthly_n: 12      # 月备份保留(0=关闭)
  manual_n: 5        # 手动/前置快照(pre-calc/pre-restore)保留份数
  daily_at: "18:35"  # 日备份时刻(收盘任务链后)
  weekly_on: "fri"   # 周备份日
```

- `core/backup.py`：`prune()` 常量改为参数；manifest 的 tag 升级为**类型字段**
  `type: daily|weekly|manual|pre-calc|pre-restore`，清理按类型各自滚动
- **完整日志**双轨：
  - 文件：`backups/backup.log`（每次快照/校验/清理/恢复一行结构化记录）
  - 库：app.db 新表 `backup_runs(id, type, started_at, finished_at, status,
    files_json, total_mb, error)` —— 供管理页/运维系统查询
- 执行方式：服务内 subprocess 调 `python core/backup.py now -t <type>`
  （复用 jobs.py 单工作线程队列，与数据任务互斥不并发写库）

**API（routes_admin.py，管理员级）**：
| 方法 | 路径 | 行为 |
|---|---|---|
| POST | `/admin/api/backup/run` | `{type}` 触发备份（manual/daily/weekly），入队返回 job_id |
| GET | `/admin/api/backups` | 备份历史（backup_runs 分页）+ manifest 详情 |
| POST | `/admin/api/backup/restore` | `{file}` 恢复（二次确认 + pre-restore 兜底） |
| POST | `/admin/api/backup/settings` | 改保留策略（daily_n/weekly_n/…） |
