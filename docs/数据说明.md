# 数据说明文档

> 配套程序: [core/](../core/)（评分系统）· 管理台 `python core/admin.py`
> 本文回答三个问题: **图表上每条线是什么、分数由什么构成、数据库里存了什么**。

---

## 1. 交互视图（sentiment_viewer.html）五联面板说明

自上而下（十字光标联动，右侧面板显示当日全部构成）：

| 面板 | 内容 | 单位/口径 | 数据来源 |
|---|---|---|---|
| ① 上证指数 K线 | 日 OHLC，红涨绿跌 | 点 | 东财→腾讯回退 |
| ② 两市成交量 | 沪市+深市成交量合计 | 亿手（1亿手=100亿股） | 同上 |
| ③ **情绪分** | 本系统核心输出，-100~+100 | 分，±60/±80 参考线，红区=狂热/蓝区=冰点 | 15 分量加权合成 |
| ④ 涨停/跌停家数 | 红柱向上=涨停家数，绿柱向下=跌停家数 | 家 | 同花顺涨停复盘 |
| ⑤ 炸板率·接力率 | 黄线=炸板率，绿线=接力率 | % | 同花顺涨停复盘 |

**④⑤从 2025-10-15 开始才有数据**：同花顺涨停复盘只保留约一年滚动历史，这是免费数据源的边界，不是程序故障。每天收盘后更新一次，数据自然滚动积累。

右侧构成面板各列含义：**原始值**（当日实际数）、**分位分**（该值在过去 250 日中的相对位置，-100~+100，条形图）、**权重**（当日实际生效权重，缺失分量自动重分配）、**贡献**（分位分×权重）。

## 2. 情绪分构成（15 个分量，权重可在管理台调整）

### 短线情绪组 20%（涨停结构，同花顺口径）

| 分量 | 原始值含义 | 方向 | 默认权重 |
|---|---|---|---|
| 涨停家数 | 当日收盘涨停的股票数（沪主板+创业板+科创板，不含ST） | 越多越热 | 4% |
| 跌停家数 | 当日收盘跌停数 | 越多越冷 | 4% |
| 炸板率 | 盘中曾涨停但收盘未封住的比例 = 炸板/(涨停+炸板) | 越高越冷 | 4% |
| 连板高度 | 当日最高连板数（市场空间板） | 越高越热 | 4% |
| 接力率 | 今日2板及以上家数 ÷ 昨日涨停家数（赚钱效应代理） | 越高越热 | 4% |

### 量能组 20%（非对称方向化：放量×当日涨跌方向；缩量恒为负，缩量涨减半）

| 分量 | 原始值含义 | 默认权重 |
|---|---|---|
| 两市成交量 | 沪+深成交量合计（手），取250日分位后乘方向 | 12% |
| 量比趋势 | 5日均量/20日均量 | 8% |

### 动量组 28%

| 分量 | 原始值含义 | 默认权重 |
|---|---|---|
| 14日RSI | 相对强弱，取250日分位 | 10% |
| 当日涨跌幅 | 上证指数日涨跌幅分位 | 8% |
| 跳空缺口 | 开盘价/昨收-1（竞价/隔夜情绪） | 5% |
| K线实体强度 | (收-开)/(高-低) 的3日均值 | 5% |

### 位置组 20%

| 分量 | 原始值含义 | 默认权重 |
|---|---|---|
| 20日乖离 | 收盘/20日均线-1 | 8% |
| 60日乖离 | 收盘/60日均线-1（慢趋势） | 5% |
| N日价格位置 | 收盘在250日高低区间的位置 | 7% |

### 波动组 12%

| 分量 | 原始值含义 | 默认权重 |
|---|---|---|
| 振幅×方向 | 日振幅分位 × 当日涨跌方向（放量大涨=热、放量大跌=冷） | 12% |

**合成方法**：每分量→250日滚动分位（(X-最低)/(最高-最低)）→中心化到±100→加权求和→EMA(3)平滑→限幅±100。
当日缺失的分量（如2025-10前的涨停组）权重自动归一化重分配给其余分量。

### 分档

| 区间 | 状态 | | 区间 | 状态 |
|---|---|---|---|---|
| -100~-80 | 极度冰点 | | +10~+30 | 中性偏强 |
| -80~-60 | 冰点/恐慌 | | +30~+60 | 偏热/发酵 |
| -60~-30 | 偏冷/退潮 | | +60~+80 | 狂热/高潮 |
| -30~-10 | 中性偏弱 | | +80~+100 | 极度狂热 |
| -10~+10 | 中性 | | | |

## 3. 数据库（core/data/sentiment.db，SQLite）

**查看工具**（任选其一）：
- **DB Browser for SQLite**（推荐，图形界面）：sqlitebrowser.org 下载 → 打开 db 文件 → 浏览数据 / 执行SQL
- VS Code 插件：SQLite Viewer 或 SQLite3 Editor，装后侧栏点开 .db 文件
- 命令行：`python -m sqlite3 core/data/sentiment.db`，如 `SELECT * FROM mood_raw ORDER BY date DESC LIMIT 10;`

### 三张表

**index_daily** — 指数日线

| 列 | 含义 |
|---|---|
| code | `1.000001` 上证指数 / `0.399106` 深证综指（东财secid格式） |
| date | 交易日 YYYY-MM-DD |
| open/high/low/close | 开高低收（点） |
| volume / amount | 成交量（手）/ 成交额（元，腾讯源为空） |
| pct_chg | 涨跌幅% |

**mood_raw** — 涨停复盘与市场统计（每交易日一行）

| 列 | 含义 |
|---|---|
| zt_count / dt_count | 涨停 / 跌停家数 |
| zb_count / zb_rate | 炸板家数 / 炸板率% |
| lb_max / lb2_count | 最高连板数 / 2板及以上家数 |
| jl_rate | 接力率% = lb2_count / 昨日涨停家数 |
| yzt_count | 昨日涨停家数 |
| prev_zt_chg | 昨日涨停股今日平均涨幅%（仅东财近月可得，暂未入评分） |
| up_count / down_count | 上涨/下跌家数（仅最新一天，乐咕源） |

**sentiment** — 每日评分结果（重算时整表重建）

| 列 | 含义 |
|---|---|
| date / score / stage | 日期 / 情绪分 / 分档文字 |
| components | JSON：当日各分量分位分 |

### 常用查询示例

```sql
-- 最近10天情绪分
SELECT date, score, stage FROM sentiment ORDER BY date DESC LIMIT 10;

-- 历史最恐慌的10天
SELECT date, score FROM sentiment ORDER BY score ASC LIMIT 10;

-- 涨停家数最多的10天(短线情绪最亢奋)
SELECT date, zt_count, lb_max, jl_rate FROM mood_raw ORDER BY zt_count DESC LIMIT 10;

-- 某日的分量明细
SELECT date, components FROM sentiment WHERE date='2026-10-09';
```

## 4. 文件产物

| 文件 | 说明 | 生成方式 |
|---|---|---|
| `core/out/sentiment_viewer.html` | 交互视图（自包含，双击打开） | `python viewer.py` |
| `core/out/publish/` | **发布目录**：sentiment_日期.html 各版本 + index.html（最新副本），整个文件夹可直接拷走部署 | 管理台"生成视图" |
| `core/out/sentiment.csv` | 全量分数+分量导出（Excel可开） | `python score.py --csv` |
| `core/out/sentiment_history.png` | 静态双面板图 | `python report.py --chart` |
| `core/config.yaml` | 默认参数（权重/窗口/数据源） | 手工编辑 |
| `core/config_override.yaml` | 管理台"保存为默认"生成的覆盖文件（优先级高于 config.yaml，删除即恢复默认） | 管理台 |

## 5. 日常流程

```bash
cd core
python admin.py --port 8599   # 过渡期旧管理台(S2后移除)
# 页面上: 看"数据状态" → 点"增量更新数据" → 需要发布时调权重 → "生成视图"
# 正式Web服务(建设中): 仓库根目录 python -m server → http://127.0.0.1:8501
```

或纯命令行：`python fetch_daily.py && python score.py && python viewer.py`

**注意**：情绪分是市场温度计，不构成投资建议；涨停池口径不含ST股，序列内部一致。
