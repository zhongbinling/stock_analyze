## 0. 总体架构与技术决策

### 0.1 技术选型（推荐方案）

| 层 | 选型 | 理由 |
|---|---|---|
| 后端 | **Flask + Jinja2 模板**（延续现有 admin.py） | 页面以服务端渲染为主，Python 单体，部署简单；避免引入 SPA 前端框架的构建链 |
| ORM | **Flask-SQLAlchemy** | app.db 全部表走模型定义，分页/CRUD/防 SQL 注入，不手写原生 SQL |
| 会话 | **Flask-Login** | 管理员/普通用户登录态管理，匿名用户识别（anonymous_user） |
| 密码 | **Flask-Bcrypt** | 账号密码安全哈希存储，禁止明文 |
| 表单 | **Flask-WTF** | 新增账号、数据源配置、定时任务等表单校验 + 全站 CSRF 防护 |
| 迁移 | **Flask-Migrate（Alembic）** | 表结构演进（新增字段等）走版本化迁移，替代手写迁移脚本 |
| 前端 | 原生 JS + fetch + CSS 变量（浅色/深色双主题） | 9 个页面体量不大；沿用 dataviz 规范色板（含暗色值） |
| 数据库 | **SQLite 双库**：`data/app.db`（账号/视图/任务，SQLAlchemy+Migrate 管理）+ `data/sentiment.db`（行情，现有轻量 SQL） | 单机规模足够；零运维 |
| 定时任务 | **APScheduler**（进程内，任务落库） | 每日数据更新→生成→发布 串联 |
| 生产服务器 | **waitress**（跨平台 WSGI，win/mac/linux 通用） | 避免 gunicorn 不支持 Windows 的问题 |

> 技术栈已确认（2026-10-15，含上述 Flask 扩展清单）。

> 备选：FastAPI + Vue3 SPA（更现代，但构建链与维护成本高，本项目不采用）。

### 0.3 视图生成与发布流水线

```
[数据更新任务] → [视图生成任务(env=测试/产线, 按生成规则)] → [发布]
                                                      └→ 产线+auto_publish → 自动发布
视图文件: views_store/{env}/{type}/{YYYYMMDD}/{run_id}.html (自包含, 沿用现有 viewer)
发布 = 登记到 published 表, 用户侧 /mkt/view/{id} 可访问; 数据库只存元数据
```

- 生成规则（view_defs）：名称 / 视图类型 / 环境(测试·产线) / 算法 / 参数(权重/窗口/年限) / cron / 是否自动发布
- 算法注册表：默认 `weighted_percentile_v21`（现行 15 分量加权分位）；预留注册接口，后续可挂新算法
- 用户侧行情页默认展示：最新已发布的产线情绪视图

### 1.3 各页面规格

**① 管理登录页 `/admin/login`**
- 账号+密码登录（限速：5 次失败锁 10 分钟）；登录成功 → 管理工作台（数据管理/数据生成/视图管理导航）
- 超级管理员引导账号：首次部署用 `python -m server.bootstrap` 命令行创建

**② 账号管理 `/admin/accounts`**（超管）
- 列表：账号名/昵称/等级/状态/创建时间/最后登录
- 操作：新增管理员(5/7/9)、新增用户(2/3)、重置密码、停用/启用、删除（删除=软删除，保留视图归属）
- 不可删除自己；操作留审计日志（admin_log 表）

**③ 数据管理 `/admin/data`**（管理员）
- 数据集总览表：数据集 / 来源类型(同花顺/东财/腾讯/乐咕/tushare预留) / 已同步条数 / 覆盖区间 / 最新同步时间 / 健康状态（缺失天数、上次任务结果）
  - 首批数据集：指数日线×2、涨停复盘池、当日涨跌家数、（预留）tushare 涨停历史/融资融券
- 更新控制区：
  - 手动：立即增量更新 / 全量刷新指数（实时日志，复用现有任务机制）
  - 策略：自动更新 cron（默认交易日 16:35）、失败重试、节假日感知（按交易日历表）
  - 数据源配置：启停源、api_key（tushare token 输入框，存 app.db，页面掩码显示）
- 任务历史：最近 20 条更新任务（时间/触发方式/结果/耗时/日志）

**④ 数据生成 `/admin/generate`**（管理员）
- 生成规则卡片列表（view_defs）：名称/类型(情绪视图)/环境(测试·产线)/算法/参数摘要/调度/自动发布开关
- 新建/编辑规则：权重 15 项滑杆（含默认与归一化校验）、窗口 N、年限、算法下拉（当前 1 项）、cron、环境、自动发布
- 立即执行某规则（实时日志）；生成历史列表（view_runs：时间/规则/状态/数据日期/文件大小/发布状态）→ 点击跳转视图管理
- 调度示例：交易日 17:00 数据更新完成后串行生成全部启用规则（依赖：更新任务成功）

**⑤ 视图管理 `/admin/views`**（运营）
- 筛选：类型 / 环境(测试·产线) / 日期区间 / 状态(已发布/未发布) / 规则名
- 列表：缩略信息+操作（预览、发布、下线、删除文件）
- 预览 = 新窗口打开 `/mkt/view/<id>?preview=1`
- 发布 = 加入用户可见清单；产线规则 + auto_publish 的由任务自动发布，页面可看到"自动"标记与手动覆盖
- 启停某条产线定期规则的自动发布

**⑥ 用户登录 `/login` `/register` `/logout`**
- 账号密码登录 / "匿名进入"按钮（直接建立 1 级会话）/ 注册（账号+昵称+密码，注册即 2 级，做基本长度校验与人机频率限制）

**⑦ 账号信息 `/me`**（2 级+）
- 账号名、昵称（可改）、权限等级（含等级说明）、上次访问时间、本机偏好（主题）；修改密码

**⑧ 设置 `/settings`**（所有会话）
- 白天/黑夜模式（CSS 变量双主题，存 localStorage + 账号字段；访客仅 localStorage）
- 语言（预留：中/英切换位）

**⑨ 行情数据 `/mkt`**（1 级+）
- 默认展示最新已发布产线情绪视图（iframe 承载自包含 HTML，顶栏显示数据日期/规则名/发布时间）
- 视图类型 Tab（当前仅"情绪视图"）；2 级以上可见"历史视图"列表入口（按日期选已发布产线视图）
- 未发布任何视图时的空态引导（指向管理端）

## 2. 数据库新增表（app.db）

```sql
users(id, username UNIQUE, nickname, pwd_hash, level INT DEFAULT 2, enabled INT DEFAULT 1,
      created_at, last_login_at, deleted_at)            -- 匿名不建行, 仅会话
sessions(由 Flask signed cookie 承担, 不落库)
admin_log(id, actor, action, target, detail, at)         -- 账号/发布等敏感操作审计
view_defs(id, name, type DEFAULT 'sentiment', env,       -- test | prod
          algo DEFAULT 'weighted_percentile_v21', params_json, cron,
          auto_publish INT DEFAULT 0, enabled INT DEFAULT 1, created_at, updated_at)
view_runs(id, def_id, status,                            -- pending|running|done|fail
          data_date, file_path, size_kb, generated_at, duration_s,
          published INT DEFAULT 0, published_at, log)
jobs(id, kind,                                           -- update|generate|publish
      status, trigger,                                   -- manual|schedule
      started_at, finished_at, rc, log)
data_sources(id, code UNIQUE,                            -- ths|eastmoney|tencent|legu|tushare
      name, kind, enabled INT DEFAULT 1, api_key, note)
app_settings(key PRIMARY KEY, value)                     -- 端口/绑定/默认主题/调度开关等
calendar(date PRIMARY KEY, is_trading INT)               -- 交易日历(由指数日线生成)
```

### S2 数据管理 + 生成任务（✅ 已完成 2026-10-15 · 执行稿）

**数据模型（app.db 新增 5 表）**
- jobs：任务历史（kind=update|generate、trigger=manual|schedule、status、rc、log 截断保留、耗时；时间戳用本地时间便于直读）
- view_defs：生成规则（name / env(test|prod) / params_json(权重/窗口/池窗口/年限) / auto_publish / enabled / cron 预留列）
- view_runs：生成记录（规则名快照、status、data_date、file_path、size、published；规则删除后记录仍可读）
- data_sources：数据源注册（ths/eastmoney/tencent/legu/tushare；启停 + api_key 掩码展示）
- app_settings(skey/value)：调度策略（auto_update / update_cron / auto_generate / generate_cron）
- 交易日历**不建表**：由"行情库最新日期==今天"推导（更新成功即今日数据在库），节假日自然跳过

**任务框架（server/jobs.py）**
- 单工作线程 + 内存队列（上限 20），手动/定时统一入队；任务体=子进程调用 core CLI（复用其断点续跑/多源回退）
- Job 行在开始执行时创建，日志逐行落库供页面轮询
- update 任务 = `fetch_daily.py` + `score.py`（cwd=core）
- generate 任务 = 按规则参数写临时 override（SENTIMENT_OVERRIDE 环境变量）→ `viewer.py --out views_store/{env}/{type}/{yyyymmdd}/{hhmmss}_{slug}.html` → 登记 view_runs；**prod+auto_publish 自动置 published**（即"发布"，S3 起用户可见；测试环境视图永不发布）

**调度（APScheduler，进程内）**
- config/server.yaml `scheduler.enabled`（S2 起默认 true）；每 5 分钟同步任务读 app_settings **热更新** cron
- 默认：周一至五 16:35 update、17:00 对全部 enabled 规则逐个 generate
- 守卫：仅**定时**生成校验"行情最新日期==今天"（节假日/更新失败自动跳过并留日志）；手动生成不受限（便于周末调参）

**页面（≥7 级）**
- /admin/data：数据集总览（名称/来源/行数/覆盖区间/最新日期/健康度、缺失天数告警）、手动增量更新（实时日志+队列状态）、更新策略、数据源表（启停/tushare token）、任务历史
- /admin/generate：规则列表（CRUD/启停/立即生成）、权重编辑器（15 分量+窗口+年限+环境+自动发布）、生成历史（含文件预览链接）
- 预览路由 /admin/runs/<id>/file：仅允许 views_store 内文件（≥5 级），路径穿越防护

**移除与迁移**
- core/admin.py（过渡期旧管理台）移除，功能并入 /admin/data 与 /admin/generate；views_store/ 入 .gitignore
